# Decentralized Applications

## DApp Overview and Architecture

DApps provide open access to blockchain features, enabling peer-to-peer transactions through a client interface and a blockchain-backed smart contract.
The architecture includes a front-end client (web, mobile, CLI, IoT) and a back-end blockchain infrastructure, with smart contracts running on the Ethereum Virtual Machine (EVM).

## Blockchain Server and Network Setup

The blockchain server concept represents the infrastructure and services blockchain provides, similar to traditional servers in web or mobile applications.
Using Ethereum's geth command, nodes are created and connected to form a peer-to-peer blockchain network, with network IDs distinguishing different public and private chains.

## Development and Testing of DApps

The course emphasizes hands-on development using the Truffle IDE, smart contracts, and web clients, including MetaMask integration.
It is common practice to develop and test DApps on local test networks before deploying them on public blockchains to ensure functionality and security.

## Dapp Definition and Components

A Dapp solves problems requiring blockchain services, typically consisting of a web front-end, blockchain back end, and connecting code.
The front-end channels user inputs to the blockchain and returns responses, initiating transactions that invoke smart contract functions.

## APIs Overview

API (Application Programming Interface) is a standard way to expose functions related to datasets and services, enabling code reusability.
APIs allow programmatic access to operations, data retrieval, and data storage, often controlled by access methods like public keys.

## Ethereum APIs for Dapp Development

Two main categories: Management APIs (admin, debug, miner, personal, txpool) for node management, and Web3 APIs (web3, eth, net) for Dapp development.
Examples include admin.addPeer() for network management, miner.start() to control mining, personal.newAccount() for account creation, and txpool.inspect() to view pending transactions.

## Web3.js and Dapp Architecture

Web3.js is a JavaScript library that enables communication with Ethereum nodes via RPC, providing access to blockchain functions and smart contracts.
A typical Dapp architecture includes multiple full nodes exposing RPC ports and APIs, with web requests handled through web3 objects in the client.

## Purpose and Use of Events

Events notify the completion of smart contract operations, such as transfers, and serve as logs for auditing contract activity.

Event listeners are set up in the application (e.g., JavaScript) to catch notifications and respond accordingly.

## Why Smart Contracts Can't Access External Data

Smart contracts must produce deterministic results to maintain blockchain consistency, so they cannot call external functions or resources directly.
Many real-world applications require external data (e.g., weather or stock prices) that is only available at execution time, not deployment.

## Importance of Standards

Standards bring order, safety, regulation, and clarity to rapidly growing technologies, as seen historically in computing and aviation.
For blockchain and DApps, standards are crucial to ensure predictable behavior and interoperability among diverse applications and tokens.

## Ethereum Improvement Proposals (EIPs) and ERCs

EIPs manage protocol specifications, improvements, and standards in Ethereum, categorized into core, network, interface, and application levels.
ERCs (Ethereum Request for Comments) are proposals for application-level standards, with ERC20 and ERC721 being key examples for tokens.

## ERC20 and ERC721 Token Standards

ERC20 defines a standard interface for fungible tokens, enabling DApps to interact, exchange, and transact tokens seamlessly on Ethereum.
ERC721 defines standards for non-fungible tokens (NFTs), which are unique and not interchangeable.
Implementing these standards requires following specified interfaces in smart contracts, ensuring compatibility and usability across the Ethereum ecosystem.

---

## Token Concepts and Standards

Fungible tokens, like ERC-20 tokens, are interchangeable and have intrinsic value, such as one US dollar or one bitcoin being equal to another of the same kind.
Non-fungible tokens (NFTs), represented by the ERC-721 standard, are unique and cannot be exchanged one-to-one, exemplified by collectibles like CryptoKitties, baseball cards, or real estate.

## ERC-721 and Its Impact

The ERC-721 standard introduced the idea that token values can vary, enabling unique digital assets and collectibles on the Ethereum blockchain.
CryptoKitties, an ERC-721 compliant DApp, demonstrated the potential and challenges of NFTs, including significant network traffic on Ethereum.
