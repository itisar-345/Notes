# Decentralized Applications

## DApp Overview and Architecture

DApps provide open access to blockchain features, enabling peer-to-peer transactions through a client interface and a blockchain-backed smart contract.  
The architecture includes a front-end client (web, mobile, CLI, IoT) and a back-end blockchain infrastructure, with smart contracts running on the Ethereum Virtual Machine (EVM).

## Blockchain Server and Network Setup

The blockchain server concept represents the infrastructure and services blockchain provides, similar to traditional servers in web or mobile applications.  
Using Ethereum's geth command, nodes are created and connected to form a peer-to-peer blockchain network, with network IDs distinguishing different public and private chains.

## Development and Testing of DApps

The course emphasizes hands-on development using the Truffle IDE, smart contracts, and web clients, including MetaMask integration.  
It is common practice to develop and test DApps on local test networks before deploying them on public blockchains to ensure functionality and security.

## Ethereum Name Service (ENS)

Describes ENS as an Ethereum-based decentralized application (Dapp) that replaces complex hexadecimal addresses with human-readable names.  
Provides basic implementation details of ENS to facilitate easier interaction with the Ethereum network.

## DApp Definition and Components

A Dapp solves problems requiring blockchain services, typically consisting of a web front-end, blockchain back end, and connecting code.  
The front-end channels user inputs to the blockchain and returns responses, initiating transactions that invoke smart contract functions.

## Front-End and Blockchain Interaction

The front-end can range from a simple command line interface to sophisticated web or mobile apps.  
Development involves web technologies like HTML, JavaScript, CSS, and frameworks such as Express, with communication to the blockchain via web3.js and JSON-RPC.

## DApp Architecture and Development Tools

The blockchain server is represented by Ethereum nodes (E-nodes) exposing RPC ports for communication.  
Smart contracts are deployed and invoked using scripts generated by Remix IDE, with plans to use IDE tools to simplify development.  
Two architecture alternatives are discussed: command line interface and web client front-ends, with the web client being more user-friendly.

## Overview of dApps

dApps are software programs that operate on the Internet without control by any single entity.  
They have existed since the early days of peer-to-peer (P2P) networks.

## APIs Overview

API (Application Programming Interface) is a standard way to expose functions related to datasets and services, enabling code reusability.  
APIs allow programmatic access to operations, data retrieval, and data storage, often controlled by access methods like public keys.

## Ethereum APIs for Dapp Development

Two main categories:  
- Management APIs (admin, debug, miner, personal, txpool) for node management  
- Web3 APIs (web3, eth, net) for Dapp development  

Examples include:
- admin.addPeer() for network management  
- miner.start() to control mining  
- personal.newAccount() for account creation  
- txpool.inspect() to view pending transactions  

## Web3.js and Dapp Architecture

Web3.js is a JavaScript library that enables communication with Ethereum nodes via RPC, providing access to blockchain functions and smart contracts.  
A typical Dapp architecture includes multiple full nodes exposing RPC ports and APIs, with web requests handled through web3 objects in the client.
